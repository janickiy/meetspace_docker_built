# MeetSpace Docker packages

Готовые серверные Docker-образы публикуются в [Releases](https://github.com/janickiy/meetspace_docker_built/releases). Исходники бэкенда находятся в [janickiy/meet-space](https://github.com/janickiy/meet-space).

Android-установщик в режиме «Готовые образы» с параметром `latest` выбирает последний опубликованный совместимый релиз, содержащий `prebuilt.json` и пакет для архитектуры сервера. Полные prerelease-сборки также участвуют в выборе. Отдельного тега `latest` нет.

Каждый релиз содержит архивы для `linux/amd64` и `linux/arm64`, SHA-256, описания обеих архитектур и общий `prebuilt.json`. В индексе `repository` указывает на этот репозиторий пакетов, `sourceRepository` — на репозиторий бэкенда, а `commit` — на полный коммит бэкенда. Внутри архивов сохраняются исходные сведения о происхождении кода и отчёты безопасности.

## Выпуск сборки

В Actions запустите **Build server Docker packages**:

- `version` — новая неизменяемая версия, например `v0.6.1-prebuilt.20261108.5`;
- `source_ref` — `main` или полный SHA коммита из репозитория бэкенда.

Workflow определяет коммит один раз и собирает обе архитектуры из него на соответствующих GitHub runners. Используются проверенные сборочные сценарии бэкенда, обязательные SBOM и проверка HIGH/CRITICAL уязвимостей закреплённым Trivy. Пакеты не публикуются, если хотя бы одна архитектура не прошла проверку. Ошибочные сборки остаются черновиками; повторный запуск требует новой версии.

После загрузки обеих архитектур workflow сверяет размеры и SHA-256 файлов с GitHub, формирует индекс и публикует релиз. Архивы и опубликованные версии не заменяются. Параметр `latest` разрешается только при создании плана установки; продолжение установки использует закреплённые версию, коммит и контрольные суммы.

Workflow использует стандартный `GITHUB_TOKEN` только для записи в этот репозиторий. Публичные исходники читаются без отдельного PAT; секрет GitHub не нужен в Android-приложении или на VPS.

Проверка генератора метаданных:

```sh
python3 -I scripts/test_release_metadata.py
```

Первый релиз может содержать уже проверенные архивы, перенесённые из Releases бэкенда без изменения их байтов. При таком переносе меняются только внешние JSON-описания URL. Генератор метаданных проверяет размер и SHA-256 архивов, но не заменяет проверку безопасности сборки и проверку содержимого установщиком.
